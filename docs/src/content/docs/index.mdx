## Two systems, one catalog

In upstream MSI the Default Stock is not a stock: `inventory_stock_1` is a MySQL view over a legacy
table, the MSI indexer skips it, and composite salability for it comes from the old CatalogInventory
indexer. Around fifty `if (default stock)` branches across twenty modules keep the two worlds apart,
so a defect fixed on one side stays open on the other.

msi-core removes the split. Every stock, stock 1 included, goes through the same MSI code path.

## Compared with Adobe's MSI

| | Adobe's MSI | msi-core |
|---|---|---|
| Default Stock | a view over `cataloginventory_stock_status` | a real index table built by MSI |
| Composite salability in stock 1 | legacy CatalogInventory indexer | MSI composite indexers |
| Stock item configuration | `cataloginventory_stock_item` | `inventory_stock_item_configuration` |
| Reservations | per stock | per source, opt-in |
| Place-order lock | per stock | per source, covering admin orders too |
| Stock change history | none | every source item change |
| Upgrade | — | schema migration with downtime, no downgrade |
| Breaks | — | raw SQL reads of `cataloginventory_stock_item` and `_stock_status` |

The module names, namespaces and service contracts stay the same, so code that goes through the MSI
and CatalogInventory APIs keeps working. [Differences from
upstream](/msi-core/reference/upstream-differences/) lists everything that changes.

## Compatibility

| Magento Open Source | Mage-OS | PHP |
|---|---|---|
| 2.4.9 | 3.x | 8.3 – 8.5 |

Composer only installs msi-core on the Magento version it was built for.

## Install

```bash
composer config repositories.msi-core vcs https://github.com/jeanmarcos-dev/msi-core
composer require "jeanmarcos/msi-core:^1.0"
```

<Aside type="caution">
On a store with data this is a schema migration with no downgrade path. Read [Upgrade from Magento
MSI](/msi-core/start/upgrade/) first.
</Aside>
